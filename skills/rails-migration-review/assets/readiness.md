# 搬家前後檢查表

從 Rails 網站搬家經驗整理的提醒，聚焦可以安排停寫維護窗口的情境。依自己的系統選用；未確認的項目留下問題即可，不把打勾當成驗證完成的證據。

## 搬家前

- [ ] 我知道目前有哪些服務與資料需要搬，哪些應繼續沿用。
- [ ] 重要結論有現場依據；文件內容、假設和未知分開記錄。
- [ ] 備份可還原，資料時間與涵蓋範圍清楚。
- [ ] 網站之外的背景工作、排程、附件與外部相依都已納入考量。
- [ ] 維護時間、費用、容量限制及需要人決定的取捨已說清楚。

## 切換時

- [ ] 我能說明何時停止來源寫入，以及如何確認；維護頁或 DNS 切換不是唯一依據。
- [ ] 在途工作與稍後抵達的外部事件有處理方式。
- [ ] 最終資料取得後，沒有漏掉來源後續變更。
- [ ] 開放前的資料與功能檢查有明確範圍，未驗證部分沒有被當成通過。
- [ ] 已想過新站尚未寫入、開始寫入後，分別如何回復或修復。

## 搬家後

- [ ] 驗收跟到使用者要完成的事情，包括相關背景結果。
- [ ] 來源與目標不會重複執行同一批工作或排程。
- [ ] 已觀察到的負載與時段有記錄，不用一般流量結果保證尖峰容量。
- [ ] 後續備份、部署、異常處理有人接手。
- [ ] 已完成、待觀察與待處理事項分開交代。

拿不準時，可以請 AI 針對相關項目說明「目前知道什麼、還缺什麼、為什麼影響決策」。填寫後的實際資訊留在私有筆記，對外只分享去識別化的方法與心得。
