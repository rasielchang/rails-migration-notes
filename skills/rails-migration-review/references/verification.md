# 驗證方法與證據界線

這些檢查問題源自 Rails 搬家經驗與事後整理，沒有附帶各框架已驗證的測試實作。先定義需要成立的結論，再選擇檢查。沒有執行的測試標成未驗證；抽樣結果不描述成完整比對。

## 分層驗證

| 想確認的事情 | 可採證據 | 單獨不足的證據 |
| --- | --- | --- |
| 使用的是預定版本與目標 | 版本識別、啟動參數的受控查核、作用對象確認 | 建置成功或名稱看起來正確 |
| 備份可用 | 隔離還原成功、範圍與時間邊界確認 | 備份檔存在 |
| 傳輸未損毀 | 來源與目的檔案校驗值一致 | 檔案大小相近 |
| 最終資料完整 | 固定資料邊界下比對結構、筆數、內容與業務關聯 | 只比總筆數或只確認資料庫可連 |
| 應用可持續新增資料 | 識別碼產生機制、必要權限與代表性功能驗證 | 舊資料可以讀取 |
| 附件可使用 | 物件可讀、關聯正確、必要的完整性比對 | 資料庫中有附件紀錄 |
| 工作權責正確 | 實際消費者、排程、租約與在途工作狀態 | 只看到一個 worker 程序 |
| 使用者流程完成 | 資料狀態、背景結果、外部結果及畫面一致 | 單一頁面成功或單次 HTTP 200 |
| 新環境可承受負載 | 可比較的基準、代表性負載及觀察窗口 | 每日訪客總量或服務能啟動 |
| 後續可維護 | 告警可接收、備份可恢復、部署方式已驗證 | 第一次人工上線成功 |

## 資料比對注意事項

比較雙方應處在相同的資料邊界；停寫搬遷可在開放前進行。開放後發生的正常變動，需要以可重建的邊界或差異紀錄另外核對。

內容摘要需有穩定的序列化規則，處理排序、空值、時間、字元表示與分隔方式。依資料規模決定全量、分區或抽樣，記錄未涵蓋範圍。不提供一套未經目標資料型別驗證的通用摘要指令。

按實際應用檢查結構、約束、關聯、序號或其他識別碼機制，以及資料庫以外的狀態。快取是否可重建要看它是否真的只存衍生資料；不可因名稱叫快取，就忽略其中的工作、鎖或必要狀態。

## 測試效果與重試

先分類檢查是否會寫入、發送通知、產生費用、改動統計或觸發外部動作。優先使用隔離環境與合成資料。正式驗收有副作用時，依已授權範圍設計識別、清理與對帳方式。

操作逾時時，先查明是否已成功。沒有冪等或去重保證的動作，不直接重做。外部服務接受請求、實際完成處理及最終收件或可見結果，應依業務需求分開查核。

## 觀察窗口與容量

觀察時間要涵蓋與服務相關的工作週期，例如下一次排程或備份，並說明仍未觀察到的時段。評估延遲、流量、錯誤及資源飽和度，再加入背景工作等待、連線與磁碟等瓶頸。[Google SRE 監測原則](https://sre.google/sre-book/monitoring-distributed-systems/)

新舊環境沒有可比較基準時，不能斷言延遲一定由搬遷造成或一定早已存在。容量調整要記錄觀察依據、觸發條件、變更所需時間及可能中斷。

## 報告用語

- 「已完成」附結果與證據範圍，不只附執行過的動作。
- 「未觀察到」限定查核來源與時間，不寫成「不可能發生」。
- 「待驗證」列出需要的條件和負責角色，不以假設補成通過。
- 「可以回復」交代資料邊界、預估耗時與演練結果，不只說舊環境仍存在。
- 對外分享只保留方法與去識別化結論；原始證據與完整操作紀錄留在私有工作區。
