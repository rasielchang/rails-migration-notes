# 搬家前後檢查表

在規劃、切換與驗收階段逐項確認，適用於可安排停寫維護窗口的 Rails 網站搬遷。每個勾選項目應有對應證據；未確認的項目記錄問題、負責角色與處理期限。

## 搬家前

- [ ] 需要搬移與繼續沿用的服務、資料範圍已列清楚。
- [ ] 重要結論有現場依據；文件內容、假設和未知分開記錄。
- [ ] 備份可還原，資料時間與涵蓋範圍清楚。
- [ ] 網站之外的背景工作、排程、附件與外部相依都已納入考量。
- [ ] 已區分一般環境設定、服務憑證與加密金鑰，列出需輪替或撤銷的項目、使用端及回復影響。
- [ ] 維護時間、費用、容量限制及需要人決定的取捨已說清楚。

## 切換時

- [ ] 來源停寫的時間與確認方式已明確；維護頁或 DNS 切換不是唯一依據。
- [ ] 在途工作與稍後抵達的外部事件有處理方式。
- [ ] 最終資料取得後，沒有漏掉來源後續變更。
- [ ] 開放前的資料與功能檢查有明確範圍，未驗證部分沒有被當成通過。
- [ ] 新站尚未寫入與開始寫入後，分別有可執行的回復或修復安排。

## 搬家後

- [ ] 驗收跟到使用者要完成的事情，包括相關背景結果。
- [ ] 來源與目標不會重複執行同一批工作或排程。
- [ ] 已觀察到的負載與時段有記錄，不用一般流量結果保證尖峰容量。
- [ ] 後續備份、部署、異常處理有人接手。
- [ ] 已驗證新憑證可用，並記錄舊憑證撤銷結果；未完成項目有負責角色與期限。
- [ ] 已完成、待觀察與待處理事項分開交代。

需要協助審閱時，可請 AI 針對未確認項目說明缺口、影響與查核方式。填寫後的環境資訊與操作證據請存放於私有工作區。

依[環境設定與憑證輪替](../references/cutover.md#環境設定與憑證輪替)安排更新與撤銷時程。疑似洩漏的憑證應立即依事件處理流程撤銷或替換，不等搬家後才處理。
